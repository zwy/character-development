# 阶段、路由与迭代

## 1. 输入路由

| 请求 | 起点 | 不应做什么 |
|---|---|---|
| 给图提取人物、补全 | S0识别已有信息，再S1 | 将不可见细节称为精确复刻 |
| 纯文字设计角色 | S0定义少量锚点，再S1 | 虚构参考图依据 |
| 有认可全身图，要继续 | 恢复状态，检查需不需要S2 | 默认从头重做 |
| 已有角色改真人、水彩等风格 | 建新分支，复用设计，重做必要定妆 | 继承旧媒介笔触或已测结论 |
| 某个地方不对 | 回到该问题所在阶段 | 推翻所有认可项 |
| 总结或出模板 | S5检查资产与证据 | 将整理版冒充测试原文 |

## 2. 六阶段细则

### S0 任务与边界

输入：图片、原提示词、用户目标、已有项目资料，均可部分提供。
输出：本轮目标、身份模式、媒介、参考职责、可见事实与需要补全的内容。
检查：是否固定角色开发而非用户扮演；是否确需世界观事实核验；是否已有可复用风格模块。
不为创作任务搜集无关背景；涉及具体原作事实、平台限制或授权判断时，按宿主能力核验，不凭角色外观推断。

### S1 全身定妆

解决整体剪影、体态、服装层次、配色、鞋履及缺失部分。优先少道具、简背景、稳定自然姿态。全身需按角色形态保留关键边界，不能给动物强加人类鞋履要求。
认可后记录全身基准。若仅提示词获认可而无实际出图反馈，记“方案认可，执行待测”，不要擅自升级证据。

### S2 身份细化（按需）

用认可全身图或已确认脸部图制作半身／头肩图。只改取景与必要光位，不重选人物，不加新妆或新装饰。决定身份基准优先级。无须细化时记录跳过理由。

### S3 多视角

默认可用“左放大半身＋右正侧背全身”，也可选三视图或分图。明确视图数量、排序、朝向、等大规则和遮挡。出现单一视角问题，先单独修该视角，再决定是否重组整张图。
背面设计用保守延续原则：复用已有结构，不无端增加徽章、口袋、尾饰或机械零件。用户希望大胆设计时可提案，但需要确认。

### S4 跨场景

选与角色气质相符、能检查身份延续的一个简单动作。一个主要道具或无道具、两三项背景、一个明确目光目标。测试脸与体态、服装、动作接触、表情和媒介统一。
通过后不自动声称所有场景稳定；用户不需要时可跳过并注明。

### S5 资产化

先核对已确认、待定与未测试的内容，再整理正常／精简前缀、场景、输入模式、完整例子和记录。已测试原文保留独立条目；模块重写为新版本，需复测标签。
命名可以在此阶段完成，也可提前；名字不充当模型身份锁定手段。默认不写长篇未核验背景故事。

## 3. 固定锚点与变化范围

固定锚点从当前角色提取，不使用通用的固定长相清单：身份与年龄感、脸或头部轮廓、比例、发型或毛色、标志性细节、默认服装层次等。
变化范围由场景决定：表情、动作、镜头、光位、背景和道具。换装作为显式分支，不能偷偷改掉默认衣服。

## 4. 局部修正过程

1. 摘要本轮偏差，区分用户反馈、可见事实与推测原因。
2. 列明必须保持的已认可项。
3. 给出一项或一组关联改动。
4. 输出可复制完整修正版，而不仅给补丁。
5. 记录父版本和变化；失败版本保留结果与结论，不用失败猜测污染主基线。

## 5. 讨论与执行切换

“先讨论”保持在方案层。用户认可方案并明确继续落地时，生成所约定的交付物，不无休止重复确认。
普通“继续”只授权当前协作流程中下一轮内容，不授权付款、外部发帖、覆盖远端文件或调用收费生图。

## 6. 最低交付与提前交付

推荐完整路线为全身、必要半身、多视角与跨场景。最低正式交付为用户认可主体定妆、锚点明确、至少一项视角或场景变化获认可、关键未决问题透明。
用户要求提前交付则标“草案／阶段版”，不能因为未完成默认路线拒绝合理整理。不要用是否创建了文件替代实际效果验收。
