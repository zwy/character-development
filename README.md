# 角色开发与提示词资产化 Skill｜使用说明

版本：1.1.0  
日期：2026-10-20

## 这是什么

一个分阶段的人机协作技能包。它帮助AI在新角色建立、参考图提取、缺失设计补全、换风格、定妆、多视角、跨场景和角色文档交付之间正确推进，并保留反馈与基准。

它不是自动生图程序，不含模型服务、收费API或批量生产系统。包内字符脚本仅做文本辅助检查，不评判视觉质量。通用Skill核心不携带缇珞的固定人设。

## 包内内容

- SKILL.md：带name与description元数据的核心入口。
- references/：阶段、输入模式、证据与验收规则、语言长度与字符预算。
- templates/：项目状态、轮次回复、提示词记录与最终角色文档模板。
- examples/：缇珞插画与真人路线案例，不是默认角色配置。
- scripts/prompt_budget.py：Python标准库字符统计和粗粒度占位符检查。

核心约定：用户未要求落地时不提前创建文件；实际测试原文不被整理版覆盖；只得到用户文字认可时不假装看过结果图；风格分支与角色实例分开管理。

## 两种使用方式

### A. 放入普通项目或聊天上下文

提供SKILL.md及当前需要的引用文件，或把解压后的文件加入支持读取文件的项目中。先确认当前AI能读取这些文件；仅上传ZIP并不保证宿主会自动解压或加载。

如果宿主不能读取相对引用，就手动提供相应workflow、input-modes、quality-checks文件。它可以作为普通Markdown规范使用，不要求专门的Skill加载器。

### B. 使用支持技能目录的工具

按具体工具的官方说明，将character-development目录放到它要求的技能位置，并确认该工具识别入口与相对文件。当前包使用通用SKILL.md入口组织，不宣称已完成某个具体客户端的适配、安装或自动激活；不同宿主的目录与支持能力应单独确认。

## 第一次这样开始

```text
请按《角色开发与提示词资产化》Skill协作。
这是一个新角色项目，我会提供参考图和可选原提示词。
先判断已有信息与需要补全的设计，输出第一轮可复制提示词。
一次只解决一个主要问题，我反馈认可后再推进。
这次先不要生成最终角色文档。
```

继续已有项目：

```text
按同一Skill继续。请先读取项目状态和对应提示词记录。
当前风格分支与基准图见我提供的附件。
不要重做已经认可的部分，按当前未解决项推进。
```

换风格：

```text
为这个已确认角色建立一个新的真人摄影分支。
保留角色识别与服装设计，转换媒介和必要比例。
旧分支保留，先做单人全身，不一次性生成全部流程。
```

正式整理：

```text
当前方向已认可，请按Skill整理角色模板文档。
保留已测试提示词的精确原文，整理版另行标注。
正常与精简前缀共享设定；统计完整示例总字符数。
未测试扩展不要写成已验证。
```

## 项目数据放哪里

templates是空白表单，不是当前项目状态。为每个实际角色复制项目状态与提示词记录，保存在用户自己选择的位置。角色实例与Skill规则分开，避免以后换角色还带入旧设定。

建议记录最少四样：当前阶段、实际基准图、精确提示词、用户反馈。缺图时写“未归档”，不编造路径。

## 字符检查脚本

需要Python 3，只有标准库依赖。在解压后的技能目录执行：

```bash
python3 scripts/prompt_budget.py my-prompt.txt --budget 2000 --strict
python3 scripts/prompt_budget.py templates/character-document.md --markdown --budget 2000
python3 scripts/prompt_budget.py my-prompt.txt --budget 2000 --strict --language en
```

- 普通模式统计整个文件，包含空格和换行；保存文件时的末尾换行也会计入。
- Markdown模式统计每个text代码块，排除围栏及围栏分隔换行。
- CRLF或CR换行统一为LF；按Python len统计，不是模型token。
- --strict遇到超预算或粗略占位符候选返回1；无此参数只报告。
- --language en额外输出等效中文字符数估计，用于判断英文提示词的预算还够不够。
- 正常运行返回0；读取或用法错误返回2。
- 模板中的占位符本来就需要保留，不能把模板检查报告当作交付失败。
- 占位符检查有局限；脚本不核验身份、服装一致性、矛盾、图片质量、授权或平台真实限制。

## 语言与字符上限

- 提示词语言跟随用户本轮的沟通语言：中文沟通用中文提示词，其他语言沟通用英文提示词。
- 平台字符上限是硬边界，超出即无法提交。即梦为 2000 字符。
- 等义英文的字符数约为中文的 3.6–5.0 倍：2000 字符的中文预算约等于 480 字符的等义英文。英文超限时的压缩顺序见 `references/length-and-language.md`。

## V1.0不强制覆盖

用户照片扮演、双主体与视频只保留扩展入口，不纳入必跑路线。不接入外部平台，不自动执行生成或覆盖既有角色文件。

## 可验收的核心行为

1. “先讨论”时不创建文档。
2. “不错，继续”只推进当前目标，不夸大证据。
3. “衣服好，脸不行”只修脸，锁定衣服。
4. 换风格另建分支，认可新图后用新分支延续。
5. 没有结果图时，不声称逐图检查通过。
6. 角色名和案例属性不污染新项目。
7. 资产化后保留原文、整理版、长度与待测边界。
8. 提示词语言跟随用户沟通语言，英文超限时按既定顺序压缩，交付前用 --strict 校验平台上限。
9. 平台上限视作硬边界：超限的示例不标为合规。
